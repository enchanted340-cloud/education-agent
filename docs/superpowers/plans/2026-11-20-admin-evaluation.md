# 管理后台实验评测页实施计划

在知序管理后台复用 `#experiments`，供汇报者展示阶段 D 的真实配对结果及四个可展开的案例。由 medium 分别实现数据接口和页面，再联调。使用现有 Python 标准库服务、原生 JS 模块和管理后台样式。

### 1. 从实验归档读取数据

- [x] 在 `webapp` 实现只读投影，在 `server.py` 注册 `GET /api/evaluation`，读取仓库同级 `experiments/stage-d-20261118/execution`。沿用服务原有的 Host 检查与静态文件白名单。
- [x] 数据契约为 `{available:true,taskCount,armCount,total,paired,improvedTaskCount,metrics,skills,cases}`。`metrics` 取自评分归档，按逐题配对分数核对。`improvedTaskCount` 为出现改善的不同教师请求数。`skills` 保存 B 对 A、C 对 A 的同题配对，含可比题数、两组主指标和首稿胜负平计数 `draftCounts`。案例为 `{task,arm,title,subtitle,requirement,versions}`。版本为 `{version,status,statement,sample,expected,findings,scores}`，其中 `sample` 为保存的输入、输出和解释，`expected` 来自逐样例复算，`findings` 为该版本的盲评发现，`scores` 为主分、样例答案分和覆盖分。未完成复审的修订稿仍可查看，状态据实际回执标明。由盲评发现、映射表、匿名包和解盲记录绑定原文与版本。归档未安装返回 `{available:false}`，损坏或不匹配显示读取失败。
- [x] 精选范围固定为 H08 A（容量 10、重量 6 的第一例），H03 A（第二例，修订前后需分别读入实际数组），H01 A（第三例，改对列号但仍缺奇数行起点、复审缺测），H06 B（学生解法限制，展示要求与题面，样例本身可正确）。接口只返回以上展示字段。访问页面无需生成题目或读取学生原始作答。

### 2. 管理后台页面

- [x] 在 `static/router.js`、`app.js`、`labels.js` 注册“实验评测”，新增 `static/pages/evaluation.js`，在 `server.py` 静态白名单放行该模块。仅从管理后台导航出现，支持直达链接。使用现有请求工具，异步加载遵守页面 epoch，跳转后不覆盖新页面。该页独立于学生与画像选择。
- [x] 页首并列展示首稿和终稿的真实分子与分母，以两条同尺度横条表现主指标，突出百分点差。标明实验范围、完整配对与缺测；下方展示样例答案、覆盖条件两个诊断指标。数字由接口计算或格式化。
- [x] 中段四项案例可键盘展开，首例默认可见。保存的题面、样例和盲评依据各有清楚位置，修订前后样例分别呈现。页尾单列同一教师请求下两种技能相对正式提示的首稿、终稿结果和各自可比题数。接口在每个技能项用 `final: {included, primary}` 补充终稿数据。注明 H06 对教师要求的不同解读如何影响结论。继承管理后台的色彩、字体和间距，窄屏时上下排列，模型文本用文本节点渲染。
